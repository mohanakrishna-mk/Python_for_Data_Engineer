## Python Library & Object Understanding — Notes

### 1. Package → Module → Class → Object

A Python library is generally organized like:

```text
Library / Package
      ↓
   Module
      ↓
    Class
      ↓
   Object
      ↓
  Method / Attribute
```

Example:

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.getOrCreate()
```

Conceptually:

```text
pyspark              → package
   ↓
sql                   → module/package
   ↓
SparkSession          → class
   ↓
spark                 → object
```

---

### 2. Object

An object is an instance of a class.

```python
class Person:
    pass

p = Person()
```

Here:

```text
Person → class
p      → object of Person
```

You can check:

```python
type(p)
```

---

### 3. Attribute vs Method

An **attribute** is accessed without `()`:

```python
object.name
object.read
object.schema
```

A **method** is called with `()`:

```python
object.show()
object.filter()
object.csv()
```

Example:

```python
spark.read
```

`read` gives you another object.

```python
spark.read.csv()
```

`csv()` is a method of that object.

---

### 4. Multiple Dots (`.`)

Multiple dots usually mean **method/property chaining**.

Example:

```python
spark.read.csv("data.csv")
```

Think of it as:

```python
reader = spark.read
df = reader.csv("data.csv")
```

So:

```text
spark
  ↓
read
  ↓
DataFrameReader object
  ↓
csv()
  ↓
DataFrame object
```

The important idea:

> **The result returned by one step can itself be an object that has more methods/properties.**

---

### 5. Method Chaining

Example:

```python
df.filter(col("salary") > 50000).select("name").show()
```

Conceptually:

```text
DataFrame
   ↓
filter()
   ↓
DataFrame
   ↓
select()
   ↓
DataFrame
   ↓
show()
```

This is why PySpark code can have many dots.

---

### 6. Return Value

Always ask:

> **What does this method return?**

Example:

```python
x = spark.read
```

`x` → `DataFrameReader`

Then:

```python
y = x.csv("data.csv")
```

`y` → `DataFrame`

Therefore:

```python
spark.read.csv("data.csv")
```

is simply a shorter way of writing those steps.

---

### 7. `self`

Inside a class:

```python
class Person:

    def __init__(self, name):
        self.name = name

    def hello(self):
        return self.name
```

Usage:

```python
p = Person("John")

p.name
p.hello()
```

`self` represents the **current object**.

---

### 8. Inheritance

A class can inherit another class:

```python
class Parent:
    def hello(self):
        print("Hello")

class Child(Parent):
    pass
```

Now:

```python
c = Child()
c.hello()
```

`Child` gets functionality from `Parent`.

Libraries use inheritance heavily.

---

### 9. How to Explore Any Library

These are very useful:

```python
type(object)
```

Find the object's type.

```python
dir(object)
```

See its available attributes and methods.

```python
help(object)
```

Read documentation.

```python
help(object.method)
```

Understand a particular method.

```python
import inspect

inspect.signature(object.method)
```

See the method's parameters.

Example:

```python
print(type(spark))
print(type(spark.read))
print(dir(spark.read))
help(spark.read.csv)
```

---

## ⭐ Main concept to remember

When you see:

```python
a.b().c.d().e()
```

Don't get confused by the dots.

Read it **left to right**:

```text
a
 ↓
b()       → returns something
 ↓
c        → property/method of returned object
 ↓
d()      → returns something
 ↓
e()      → method of returned object
```

### The key question is always:

> **"What object do I have after each `.` or `()`?"**

Once you understand this, learning the **PySpark library/API** becomes much easier.
